# DotaCustoms

Хаб кастомных игр Dota 2 — **Custom Hero Chaos (CHC)** и **Ratten Run (RR)**.

Настольное приложение (Electron) с собственным локальным сервером и базой.
Ничего не отправляется наружу: справочник героев, предметов и талантов лежит
на диске, база — в профиле пользователя, сервер поднимается на `127.0.0.1`
на случайном порту и доступен только самому приложению.

---

## Как скачать

Готовый `.exe` лежит в релизах: **Releases** → последний → `DotaCustoms 1.0.0.exe`
(≈94 МБ, Windows x64). Программа портативная: установки не требуется, файл
можно запустить с флешки. Распаковывается сам — это обычный portable-артефакт.

Первый зарегистрированный аккаунт на общей базе становится администратором.

### Где смотреть чужие билды

Обычно приложение работает офлайн, и база — твоя личная. Чтобы видеть билды,
топы и ветки других, хост включает **«Админка → Общий доступ»**, после чего
остальные открывают в браузере ссылку вида `http://<его-IP>:48711`.

Всё, что видно по этой ссылке, — одна база: билды, топы, ветки, лайки,
комментарии, модерация. Свои записи участники добавляют туда же, поэтому
история общая и сохраняется. Программу при этом качать не нужно — хватает
браузера.

Подробности и ограничения — в разделе «Общая база» ниже.

### Про данные

```bash
npm run data:fetch    # dotaconstants + dota2.com (герои, предметы, патчи, herodata)
npm run data:build    # data/dota.json — то, что раздаёт backend
npm run data:images   # ~1270 обычных + 30 кастомных иконок в app/images, ~35 МБ
npm run icon          # иконка приложения: руна ᛝ рисуется кодом, без картинок
```

`herodata` с dota2.com — источник истины по составу героя: он отдаёт
ровно те способности и таланты, которые доступны в игре. Без него в
редакторе появлялись бы внутренние способности (`antimage_ebb`), а у
15 героев не было бы талантов вовсе. Количество уровней выбора талантов
тоже берётся оттуда: в патче 7.41 у героя 8 талантов, то есть **4** выбора
(8/10/15/20), и `maxTalents` в API подстраивается автоматически.

Чтобы вернуть иконки с CDN Valve и убрать 35 МБ из сборки:

```bash
npm run data:images -- --remote
rm -rf app/images
```

### Почему `node-sqlite3-wasm`

Нативный `better-sqlite3` требует пересборки под каждую версию Node и
Electron, а это хрупко. WASM-вариант не трогает toolchain. Но у него есть
две особенности, поэтому весь SQL ходит через `backend/sqlite.js`:

1. **Параметры принимаются только массивом.** `stmt.run(a, b, c)` молча
   привязывает только первый аргумент. Обёртка принимает и так, и так.
2. **`on conflict … do update` выполняется неверно** — значения из
   `excluded` приходят пустыми. В проекте его нет: голоса пишутся через
   `delete + insert`, настройки — через `update`.

### Блокировка базы и аварийное завершение

Драйвер держит базу каталогом `dotacustoms.db.lock` и снимает его только при
штатном выходе. Закрыли через диспетчер задач, убили процесс, выключили
компьютер — каталог остаётся, и **все следующие запуски падают** с
«database is locked». Пользователь при этом ничего не может сделать:
база выглядит исправной, а программа не запускается.

Поэтому `openDatabase` рядом с базой держит `dotacustoms.db.pid`. Перед
открытием проверяем: если каталог `.lock` на месте, а процесса с таким pid
уже нет — блокировка протухла, её можно снять. Живой процесс базу не
отбираем. Плюс в `main.js` стоит `app.requestSingleInstanceLock()`: второй
клик по иконке фокусирует уже открытое окно, а не лезет в ту же базу.

Обе ситуации проверяет `npm run check:window` — он специально убивает
приложение и поднимает заново.

### Проверки

`npm test` гоняет три независимых прогона:

- **API** — права, валидация, пагинация, модерация, баны, откат прав;
- **renderer** — статическая сверка всех `store.*` / `ui.*` / `api.*`
  обращений с реально экспортируемыми членами;
- **интерфейс** — все 23 маршрута отрисовываются в минимальном DOM против
  живого backend-а: гость, вошедший, Coach, админ, плюс markdown и права.

Последний прогон поднимает свой backend на временной базе, поэтому не
зависит от запущенного приложения.

Отдельно — `npm run check:window`. Он поднимает настоящий Electron на
временном профиле, подключается к нему по CDP и спрашивает у живого окна:
изолирован ли контекст, грузятся ли иконки с диска через CSP, не падает ли
какой-нибудь экран, чисто ли консоль. Это единственный прогон, который
видит настоящий Chromium — остальные крутятся в своём DOM.

## Структура данных Dota

Всё, что показывает приложение, лежит в `data/dota.json` и собирается из
двух источников:

| Источник | Что берём |
| --- | --- |
| `odota/dotaconstants` | Герои, предметы, все способности, список патчей |
| `dota2.com/datafeed/herodata` | **Состав каждого героя**: ровно те способности и таланты, что доступны в игре, и в правильном порядке |

Второй источник принципиален. По одним ключам odota не отличить боевую
способность от внутренней: у Антимага в базе 18 записей, из которых в
билд-редакторе имеют смысл пять (`Mana Break`, `Blink`, `Counterspell`,
`Persecutor`, `Mana Void`). Остальные — `antimage_ebb`,
`antimage_mana_void_persecutor` и подобные служебные. А у 15 героев
(Венге, Виндрангер, Зюс, Не-крозлит…) имена талантов вообще не содержат
ключ героя, так что определить их владельца иначе невозможно.

Из herodata же берётся число уровней выбора талантов: в патче 7.41 у героя
8 талантов, то есть **4** выбора (8/10/15/20). `meta.talent_levels` едет
в датасет, `/api/config` отдаёт его интерфейсу, и `LIMITS.maxTalents`
подстраивается автоматически — жёстко зашитых «пяти уровней» в проекте нет.

### Общая база: почему другие видят билды

Пользователь жаловался, что «нет базы, которая давала бы другим видеть
билды». База всегда была одна — просто она лежала в файле на этом
компьютере и слушала только `127.0.0.1`.

Теперь есть **общий доступ по локальной сети** (выключен по умолчанию,
включается администратором в «Админка → Общий доступ»):

| | выключено | включено |
|---|---|---|
| адрес | `127.0.0.1:случайный` | `0.0.0.0:48711` |
| кто видит базу | только этот компьютер | все в той же сети |
| как заходят другие | — | обычным браузером по ссылке `http://192.168.x.x:48711` |

Сервер отдаёт те же файлы интерфейса, что и окно приложения, поэтому по
ссылке открывается полноценный хаб: каталог героев, билды, топы, ветки,
регистрация. Никаких внешних аккаунтов не нужно.

При переключении порт меняется, поэтому `app/js/api.js` узнаёт адрес по
требованию (`app:port` через preload) и один раз переспрашивает его при
неудаче — окно перезагружать не нужно.

#### Про раздачу exe и общую базу — важно понимать разницу

Релиз на GitHub и общая база — это две независимые вещи, и их часто
путают:

| | что даёт | чего не даёт |
|---|---|---|
| **`.exe` в Releases** | программу можно скачать и запустить на любом Windows-компьютере | чужих билдов: у каждого своя база на своём диске |
| **общий доступ** | одну общую базу: билды, топы, ветки, лайки, комментарии, всю историю | самой программы: участникам достаточно браузера |

Поэтому «скачали с GitHub» не значит «увидели чужие билды». Чтобы увидели,
нужно открыть ссылку хоста, у которого включён общий доступ. GitHub хранит
файлы, а не работающую базу, и синхронизировать базы между установками он
не умеет.

Если нужен хаб не в одной сети, а через интернет, текущей схемы мало:
тогда базу надо выносить на сервер, а приложение научить ходить к нему
вместо локальной базы. Это другая архитектура, не переключатель.

#### Где лежит база и как её не потерять

Файл базы — `%APPDATA%\dotacustoms\data\dotacustoms.db`. Бэкапы
автоматически пишутся в `…\data\backups\` (последние 12 копий), а вручную
базу можно выгрузить через «Админка → Обзор → бэкап».

Если включён общий доступ, вся история живёт именно в этом файле на машине
хоста. Пока хост выключен, остальные не видят ничего — это не кэш и не
зеркало, а одна база. Хотите страховку — копируйте `dotacustoms.db` на
диск, пока программа закрыта.

## Ростер героев

В справочнике Dota 127 героев, а в Custom Hero Chaos и Ratten Run играют
не все. Список задаётся **прямо в приложении**: кнопка «⚙ Ростер режима»
внизу окна выбора героя (в редакторе билда и при создании топа).

Право есть у админа и у Coach с правом на этот режим. После сохранения
выбор героя и в билде, и в топе показывает только отмеченных героев,
а заголовок — «Выбор героя — N в игре».

**Пустой ростер = ограничений нет**, доступны все 127. Поэтому по
умолчанию приложение ведёт себя как раньше, и сломанный список не может
молча убрать всех героев.

Где это лежит:

| Где | Что | Когда применяется |
| --- | --- | --- |
| таблица `hero_rosters` в базе | основной вариант, правится из UI | сразу |
| `data/custom/rosters.json` | запасной, для образа в репозитории | после `npm run data:build` |

```json
{ "chc": ["antimage", "nevermore"], "rr": [], "excluded": [] }
```

Хранятся **ключи** героев (`heroes[].key`), а не `id`: ключ читаемый и не
меняется при пересборке справочника. Неизвестный ключ отвергается с
ошибкой — опечатку должен видеть тот, кто её сделал, а не тот, кто потом
не может найти героя.

Если герой уже привязан к билду, а потом его убрали из ростера, редактор
показывает пометку «нет в ростере»: молча пропавший из выдачи билд
выглядит как потерянный.

### Почему герой в билде необязательный

В CHC и Ratten Run героя часто назначает сама игра, и билд «на весь
ростер» — обычное дело. Поэтому в редакторе герой это одна строка «Герой:
не привязан», а не плитка во всю ширину, и `hero_id` в базе допускает
пустое значение — такой билд сохраняется и показывается в общей ленте.

Навыки, наоборот, без героя выбрать нельзя: в CHC герой это статовая
оболочка, а набор способностей — осмысленная вещь. Поэтому панель скиллов
с героя начинается: сначала выбираешь героя, потом кликаешь по нему (или по
кнопке «⛭ Скиллы» в строке героя) и получаешь выбор из **пула CHC** — всего
справочника боевых умений (734 шт.), а не только умений своего героя.
Переключатель «Способности героя / Пул CHC» переключает источник, лимит
`maxSkills` — 20.

### Стадия и сложность убраны

В билде больше нет полей «стадия» (линия / мид-гейм / лейт) и «сложность»
(1–5 звёзд): они требовали заполнения, но ничего не давали читателю, а тайминг
и так описывается в заметке к предмету и в описании. Поля убраны из редактора,
из фильтра списка, из карточки и со страницы билда; колонки в базе и валидация
на входе остались, чтобы старые билды и ссылки вида `?stage=laning` не сломались.

## Кто пишет, кто смотрит

Правило простое, зашито в `requireStaff` на создании билдов, топов, веток
и гайдов:

| Кто | Что может |
|---|---|
| Coach или администратор | создавать билды, топы, ветки и гайды — публикуется сразу, видно всем |
| обычный игрок | голоса, комментарии, ответы в ветках, жалобы и заявления |
| гость без входа | только смотреть |

Очереди проверки больше нет: раз пишут только проверенные люди, всё
опубликованное видно всем сразу. Черновик — исключение: его видит только
автор, пока сам не опубликует.

Технически механика очереди осталась (`/api/admin/queue`, approve/reject,
уведомления, письма): туда попадают черновики, у них статус pending.
Поэтому «Админка → Очередь» обычно пуста — и это нормально, а не баг.

Правка и удаление — как раньше: автор и администратор. Подтверждение от
Coach (галочка «Проверено») — отдельной кнопкой, тоже Coach и админ.

## Топы как тир-лист

Раньше позиции топа были плоским списком со стрелками «вверх/вниз» и
выпадающим выбором тира. Сортировать по тирам в таком виде невозможно — а
именно сортировка по тирам и есть смысл топа. Сейчас это доска, как на
tiermaker.com:

```
┌──┬──────────────────────────────────────────────┐
│ S │ [карточка] [карточка]                       │
│ A │ [карточка]                                 │
│ B │ [карточка]            ← сюда бросают мышью │
│ C │                                            │
│ D │                                            │
└──┴──────────────────────────────────────────────┘
```

- **перетаскивание** мышью: карточка между строками и внутри строки;
- кнопки **▲/▼** и **✕** на карточке — чтобы работало без мыши;
- **«Разложить по тирам»** раздаёт позиции поровну S…D, дальше руками;
- строки видны всегда, даже пустые: сразу понятно, куда класть;
- счётчик внизу показывает, сколько позиций без тира — такие не считаются.

Логика перестановок вынесена в чистые функции в `app/js/tierboard.js`
(`moveEntry`, `shiftEntry`, `renumber`, `applyRowOrder`) и проверяется
тестами без браузера: перетаскивание в упрощённом DOM не воспроизвести,
а ошибку в сортировке — легко.

## Заявления в свободной форме

`/reports/new` — форма без привязки к объекту: человек пишет **тему** и
**текст** сам. Заявка уходит администратору, он видит ник автора и решает:
принята или отклонена. Автору приходит уведомление и письмо с решением и
комментарием администратора.

Список — с разбивкой на страницы, фильтрами по статусу и типу. Отдельные
жалобы на конкретный контент (билд, ветка, комментарий) никуда не делись:
это `POST /api/users/flags`, они показываются во вкладке «Жалобы».

## Почта

SMTP-клиент написан вручную в `backend/mailer.js` — шесть команд
протокола не тянут в проект зависимость.

Письма **никогда не отправляются прямо во время запроса**: решение
кладётся в таблицу `email_queue`, отправка — отдельным шагом. Иначе
недоступный SMTP превратил бы «принять заявку» в ошибку, и человек
потерял бы текст обращения.

Настройка — «Админка → Почта»: сервер, порт, логин, пароль, адрес
отправителя и кнопка «отправить тестовое». Поддерживается SMTPS (465) и
`AUTH LOGIN` (587). Тема письма кодируется в `=?UTF-8?B?…?=`, иначе
русский текст приходит кракозябрами.

## Что значит «база сохраняется»

На вопрос «почему не сохраняется» добавлен отдельный прогон
`npm run test:save`. Он проверяет не ответы API, а **сам файл базы**:

```
зарегистрировались → собрали билд и топ → закрыли программу →
открыли файл dotacustoms.db напрямую → убедились, что строки там есть
→ запустили заново → проверили, что контент на месте →
подтвердили билд как админ → закрыли → снова прочитали файл
```

Это важно: проверка «сохранилось» по ответу API ничего не доказывает —
ответ можно вернуть и не записать. Здесь сверяется диск.

## Сессия переживает перезапуск

Раньше секрет подписи токенов генерировался заново при каждом старте
процесса. Токен, выданный вчера, сегодня не проходил проверку HMAC,
интерфейс получал 401 и стирал токен — отсюда «постоянно забывает меня».

Теперь секрет лежит в таблице `settings` рядом с базой и переживает и
перезапуск, и обновление программы. Регрессия закрыта отдельным
прогоном `npm run test:session`, который поднимает сервер, регистрируется,
закрывает базу, поднимает заново и требует, чтобы **тот же токен** снова
работал.

## Данные переживают обновление

- Схема создаётся через `create table if not exists` — новая таблица
  безопасно появляется при первом запуске новой версии.
- Изменения существующих таблиц идут через список `MIGRATIONS` в
  `backend/db.js`. Там только `ADD COLUMN` и `CREATE INDEX`; ни одна
  миграция не делает `DROP`.
- Перед первой применённой миграцией база копируется в
  `<данные>/backups/`, хранятся последние 12 копий.
- Применённые миграции записаны в таблицу `migrations`, повторный запуск
  их не дублирует.

Чтобы откатить обновление, достаточно закрыть программу, заменить файлы
и положить на место копию из `backups/`.

## Кастомные предметы CHC

В `data/custom/chc-items.json` лежат **30 предметов**, которых **нет** в обычном
справочнике Valve: у них нет ни id, ни иконок на CDN. Они живут только внутри
кастомных игр — Custom Hero Chaos и Ratten Run. Источник — гайд
«Custom Hero Chaos and Ratten Run» (tv/kub3ik67, обновлён 23.06.2026);
Kast и Timber Saw Wheel не показаны в нём и оставлены из гайда 2024 года.

```
data/custom/chc-items.json     каталог: группы, описания, цены, характеристики, цепочки
scripts/fetch-custom-images.js тянет иконки с серверов Steam в app/images/custom/
scripts/build-dataset.js       раздаёт каталог в data/dota.json
app/js/views/custom-items.js   экран справочника
```

Каждому предмету синтетический id из диапазона **900000+** — он не может
пересечься с настоящими (максимум Valve около 35 000). Поэтому в редакторе
билда кастомный предмет ничем не отличается от обычного: `store.anyItemById()`
находит оба по id, а в списке выбора кастомные помечены и стоят в конце.

Предметов в билде бывает **больше шести** — как и в игре: съеденные
Aghanim's Shard, Moon Shards и книги идут в тот же список, общий лимит
поднят до 12 (`maxItems` в конфиге). Отдельной категории нет: порядок
списка = порядок покупки.

Скиллы в билде — не только способности выбранного героя: CHC раздаёт навыки
из общего пула любых героев. В редакторе сначала выбирается герой, затем
клик по нему открывает выбор из **пула CHC** — всего справочника боевых умений
(734 шт.) с поиском. Переключатель «Способности героя / Пул CHC» меняет
источник, лимит — 20 скиллов (`maxSkills`).

id кастомных предметов **стабильные** — выводятся из ключа (FNV-1a), а не из
индекса в списке. Раньше добавление предмета в середину каталога сдвигало все
следующие id, и сохранённые билды молча превращались в другие предметы. Старые
индексные id (900000–900018) сохранены в `custom_id_aliases` — сборки,
созданные до перехода, продолжают находить свой предмет.

Главное в каталоге — поле `related_abilities`. Оно связывает предмет с
настоящими умениями героев, чтобы было видно механику:

| Предмет | Похоже на |
| --- | --- |
| Azuresong Mageblade | филактерия (Bloodstone) |
| Timber Saw Wheel | Timbersaw: Timber Chain, Whirling Death |
| Gang Ghost Stories | Дарк Виллоу: Shadow Realm, Bramble Maze |
| Gang Meal Voucher | Lone Druid: Spirit Link |
| Replica Rackatee, Beadie's Boomstick | Sniper: Shrapnel |
| Dark Moon Shard | Moon Shard |
| Torture Pipe | Pipe |

Ссылки проверяются при сборке датасета: если умение или предмет из
`related_abilities` переименуют в Valve, `npm run data:build` напишет о битой
ссылке, а не сломает карточку молча.

Иконки лежат локально. Решение «иконки на диске, а не в CDN» записано в
`data/base/image-mode.json`, потому что `data:build` перезаписывает `dota.json`
и без этой пометки пересборка вернула бы Valve CDN, потеряв офлайн-режим.
Иконки 28 предметов вырезаны из скриншотов гайда (пометка `icon_from: 'crop'`),
и `fetch-custom-images.js` их не перекачивает даже с `--force`.

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `DOTACUSTOMS_DATA` | Каталог базы и данных. По умолчанию — `.data/` рядом с проектом, в Electron — `%APPDATA%/dotacustoms/data`. |
| `DOTACUSTOMS_DEBUG=1` | Добавляет стек ошибок в ответы API — незаменимо, когда ловишь 400. |
| `DOTACUSTOMS_SEED_ADMIN=1` | Заводит аварийного админа `admin` / `dotacustoms` при пустой базе. |

Если приложение всё же не запускается, лог всегда свежий и лежит здесь:

```
%APPDATA%\dotacustoms\logs\dotacustoms.log
```

Ручная чистка (база и все пользователи пропадут):

```powershell
Remove-Item "$env:APPDATA\dotacustoms\data\dotacustoms.db.lock" -Recurse -Force
```

## Безопасность

- `contextIsolation: true`, `nodeIntegration: false`, в preload торчит только
  база локального API.
- CSP: скрипты и шрифты только со своего origin, `connect-src` — исключительно
  `127.0.0.1`, никаких навигаций наружу.
- Пароли — PBKDF2 с солью, сессии — случайные токены в БД, пароль админки
  ничем не защищает, но и не отдаёт доступ наружу: сервер не выходит в сеть.
- Пользовательский markdown экранируется целиком, HTML из сообщений не
  подставляется.
